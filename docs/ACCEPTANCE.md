# Приёмка и необходимые проверки

Тесты домена используют управляемые время и random. Интеграционные проверки persistence — SQLite. Telegram API заменяется fake; отдельная ручная репетиция на тестовом боте.

## Регистрация и права

- Повторный /start сохраняет Participant, очередь, Cursor, кулдаун и баллы.
- Два человека с одинаковым именем различаются стабильным номером.
- Неорганизатор не может принять заявку даже с известным callback payload.
- Организатор не может сменить state/DQ. Суперадмин делает это только через разрешённый личный chat.
- Привилегированный callback от неверного actor или chat не меняет БД.

## Очередь

- Бакеты 1,2,6 при непустых пулах дают начало [1,2,6,1,2], следующий номинальный бакет 6.
- Рандом с фиксированным seed воспроизводим; рестарт не перемешивает порядок.
- Один пустой пул пропускается, Cursor обновляется после фактически выбранного бакета.
- Если все пулы пусты, Refill завершается без цикла; очередь допускает 0–4.
- GetTask берёт голову, создаёт единственный Active, немедленно пополняет до 5 при наличии пула.
- Skip добавляет прямо в хвост при длине 5 → получается 6; Cursor не меняется.
- После уменьшения 6→5 обычного пополнения нет; после 5→4 оно возобновляется.
- Несколько реджектов могут дать очередь >6; порядок возвратов сохраняется.
- Reject одноразового создаёт новую возможность в Queue, историческая Rejected сохраняется.
- Approve одноразового не возвращает задание никуда.
- Approve повторяемого при длине 5 возвращает в пул правильного бакета, не меняет очередь/Cursor.
- Approve повторяемого при длине <5 может попасть в Queue только через обычный Refill, с обычным сдвигом Cursor.
- Pending-задание не находится одновременно в пуле/очереди и не выдаётся повторно.
- Прямой возврат выполняется до Refill. Дубликат решения не возвращает задание ещё раз.
- Пример из QUEUE.md воспроизведён отдельным тестом.

## Ответы и кулдауны

- Без Active фото не создаёт Submission.
- Фотоальбом даёт один кандидат/вопрос и одну Submission с полным порядком фотографий.
- Новый кандидат инвалидирует кнопку предыдущего; старый callback без эффекта.
- Подтверждённый ответ нельзя заменить редактированием/новым сообщением.
- Skip с кандидатом инвалидирует кандидат и его кнопки.
- N1 от Skip, N2 от Confirm; до порога GetTask запрещён, ровно на пороге разрешён.
- Approve/Reject/повторный /start не продлевают кулдаун.
- Новое задание доступно после N2, хотя предыдущий ответ ещё Pending.
- После рестарта сохраняются Active, candidate media, Queue/Cursor, Pending, NextTaskAvailableAt.

## Модерация, доставка, аудит

- Два организатора одновременно Approve → одно решение, один ScoreEntry, один возврат repeatable.
- Одновременные Approve/Reject → один финальный результат.
- Выбор Reject-причины, пока другой одобрил, не меняет Approved.
- Сбой Telegram после commit не теряет Submission/баллы/аудит; доставка возобновляется.
- Неполное копирование альбома не считается полным архивированием.
- До полного архива cleanup не выполняется.
- Сбой удаления не откатывает решение; карточка помечается обработанной, кнопки отключаются, retry видим.
- Поздно доставленная карточка для уже решённой заявки не показывает действующие кнопки.
- Блокировка бота участником не блокирует проверку и архивирование.
- Повторный Telegram update после рестарта не дублирует регистрацию/ответ/награду.
- Telegram-журнал содержит actor, действие, ссылки на сущности; его недоступность не откатывает БД.

## Игра, рейтинг, DQ

- Registration разрешает регистрацию, запрещает GetTask.
- Open разрешает регистрацию и игру.
- CloseIntake закрывает и выдачу, и Skip, и Confirm, включая старые кнопки; Pending остаются проверяемыми.
- Гонка Confirm/CloseIntake имеет один корректный результат, без частично принятой заявки.
- Finalize с Pending запрещён; ForceFinalize требует отдельного подтверждения.
- ForceFinalize делает остаток Unreviewed без наград, фиксирует аудит и snapshot.
- Гонка Approve/Finalize не меняет результат после Finished.
- Последующий /start/старые callback после Finished не меняют snapshot.
- При равных баллах выигрывает меньший max(SubmittedAt) Approved-ответов, даже если ApprovedAt позже.
- Pending/Rejected/Unreviewed не влияют на tie-break. Полное равенство разрешается стабильным ID.
- DQ исключает из рейтинга и запрещает игровые команды, не стирает историю; Pending можно проверить.
- Reinstate возвращает исходный результат/прогресс, не сбрасывает кулдаун.
- Нулевые результаты имеют стабильный порядок без ошибок max(empty).
- Топ-10 и личное место вычисляются одним полным порядком.
